01

Update the two Supabase functions

Open your Flight Deck project’s Edge Functions. Replace each existing function’s index.ts with the complete current file below, then deploy each one.

On GitHub, click Raw to copy the entire file. Keep Verify JWT off for these two functions: the supplied code validates the user session or device token itself. No new database or SQL migration is needed.

Updating GitHub Pages updates the website only. You must deploy these two Supabase functions separately for the new sensor messages and PWM-only output fields.
02

Add the aircraft’s device credentials

In Supabase, open Edge Functions → Secrets. Add these values. The workspace UUID is in FLIGHT DECK Settings → Account & permissions; use your owner workspace.

The generator does not send or store the token. Copy it into Supabase Secrets and your local Secrets.h. It is separate from your publishable key and email verification code. Do not put it in GitHub, browser configuration or chat. Replacing an existing server token disconnects clients using the old one.

03

Configure and upload the NodeMCU

  1. Download and extract the firmware ZIP above. Open FlightDeck_Node_Live.ino.
  2. In Arduino IDE, install esp8266 by ESP8266 Community 3.1.2 and ArduinoJson 6.21.5.
  3. Copy Secrets.example.h to Secrets.h, keeping it beside the sketch. Replace the three placeholders:
constexpr char WIFI_SSID[] = "YOUR_MIFI_NAME";
constexpr char WIFI_PASSWORD[] = "YOUR_MIFI_PASSWORD";
constexpr char DEVICE_TOKEN[] = "THE_SAME_TOKEN_AS_SUPABASE";
  1. Select NodeMCU 1.0 (ESP-12E Module), CPU 160 MHz, and the correct USB port.
  2. Disconnect the Nano↔NodeMCU UART wires while uploading. Upload to the NodeMCU only; then reconnect the crossed UART with power disconnected.
Need the ESP8266 board package URL?

Add this under Arduino IDE Preferences → Additional Boards Manager URLs:

https://arduino.esp8266.com/stable/package_esp8266com_index.json
Use a 2.4 GHz WPA2-compatible MiFi network with internet access. For setup, remove the propeller and isolate actuator power. The NodeMCU UART uses binary data at 38400 baud, 8N1; use local diagnostics instead of Serial Monitor text.

Available with this firmware

Acceleration X/Y/Z, angular rates, chip temperature, estimated pitch/roll, sample rate, calibrated aircraft voltage, Wi-Fi signal, Nano UART/radio state and reported output PWM.

Shown as Unknown or unavailable

Transmitter voltage and raw inputs are absent from the current Nano UART packet. GPS, heading, altitude, speed, measured servo angles and arm state are not inferred.

Battery voltage stays Unknown until you calibrate Config.h. Verify the physical ADC limit before connecting the sensor; never connect the 12 V pack directly to A0. MPU axes are an example mounting and must be checked. Read the full guide for calibration.
05

If readings do not appear

In the MiFi’s connected-device list, find flight-deck-node. On the same Wi-Fi, open http://THE_ASSIGNED_IP/ to see its read-only diagnostics page. It shows MPU/UART health, raw battery ADC and the last upload result.

DiagnosticWhat to check
200 · AcceptedDashboard workspace and aircraft ID must match server settings. Select LIVE.
400 · Bad messageUpdate the ingestion function and check the aircraft ID.
401 / 403Matching device token and the documented Verify JWT setting.
422 · Old sampleMiFi performance and UTC clock. Samples over 2 seconds old are rejected.
Clock / TLS / DNSInternet, network-time access and certificate trust. Do not bypass TLS verification.
MPU / UART missingWiring, address 0x68/0x69, shared ground and matching 38400-baud Nano protocol.

The upload target is 5 Hz; actual performance depends on the ESP8266 and mobile network. TLS may interrupt sampling. The display preserves missing data and marks stale readings. No browser actuator commands are enabled.

Firmware and web contracts have automated checks. Your physical wiring, MiFi connection and calibration still require bench verification. This release is not a validated autopilot.
